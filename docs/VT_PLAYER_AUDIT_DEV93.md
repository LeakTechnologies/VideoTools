# VT_Player audit — dev93 baseline

Date: 2026-10-12. Audited commit: `abab4fca`. This is an audit and repair plan; no playback implementation changed and no runtime acceptance is claimed.

## Assessment

The native player builds, but its transport controls and resource lifecycle cannot currently guarantee that the displayed frame, timeline, audio and active source agree. Repair correctness and cancellation before tuning decode speed. A passing test suite does not establish usable playback: `internal/ui`, Player and Trim report no test files, while the media tests mostly exercise queues, clocks and metadata without real playback.

The active route is Player module → shared Convert video pane → `ui.InlineVideoPlayer` → `media.PlaybackEngine` → FFmpeg `Engine` → Fyne raster / oto audio. `native_media.go` shares one primary and one preview instance across modules. The separately named `internal/player.VTPlayer` factory is legacy plumbing: its native constructor returns an error and Auto selects ffplay. It is not the shipped inline player's backend selection mechanism. The DVD pane creates a separate InlineVideoPlayer.

## Evidence register

Confirmed means the defect is demonstrable from the present implementation. User-visible frequency, crash reproduction and performance costs remain unmeasured until a controlled playback session.

| ID | Priority | Finding and evidence | Required repair |
|---|---|---|---|
| P01 | P1 | **Incorrect FFmpeg seek constants.** `internal/media/engine.go:117` defines FRAME=1, BACKWARD=2 and a synthetic ACCURATE=8. Installed `C:/ffmpeg/include/libavformat/avformat.h:2475` defines BACKWARD=1, BYTE=2, ANY=4, FRAME=8; there is no ACCURATE flag. `playback.go:156` sends 2\|8 with timestamps: byte/frame addressing, not precise time seeking. The Frame mode sends backward=1 with a timestamp. Header documentation also says BACKWARD is ignored by avformat_seek_file. | Use C's constants and implement precise time seeking by seeking to a decodable keyframe and decoding forward to the requested PTS. Verify all modes against actual returned PTS. |
| P02 | P1 | **Scrubbing does not commit playback position.** Convert `convert_player_native.go:249` and Trim `view.go:128` call ScrubTo. `inline_player.go:991` changes the widget time and requests the private scrub decoder. `scrub.go:315` seeks only its own format context; `flushEngineQueues` disrupts live video/audio buffers but does not reposition the live demuxer or reset its clock. No drag-release commit is wired in these paths. | Keep preview scrubbing separate from a final authoritative Engine.Seek; gate competing playback presentation while scrubbing and publish the decoded PTS. |
| P03 | P1 | **Newest seek requests are discarded.** Both constructor OnSeek and `SmoothScrubbing.RequestSeek` use capacity-one channels with a default drop. This retains an older pending request and can discard the drag's final position. Inline Seek ignores Engine.Seek's returned error and displays the requested time even if seeking failed (`inline_player.go:824`). | Replace pending intent with the newest request; surface failures; update time only from an accepted decoded position. |
| P04 | P1 | **Playback ownership is not enforced.** Pause clears a boolean without joining the existing playbackLoop; Play can spawn another before the previous NextFrame returns. Seek and Step also consume NextFrame independently. playbackLoop re-reads `v.engine` each iteration rather than binding to a session; its comment promising exit when the engine changes has no identity comparison. It does not revalidate after a blocked frame read. | One presentation consumer per session; cancel and join the old consumer before restart. Validate session identity after waits and inside queued UI callbacks. |
| P05 | P1 | **Load/Close can resurrect a stale source.** `loadViaOpen` performs open/grab outside the mutex and publishes its engine unconditionally (`inline_player.go:613`). Two overlapping loads can finish out of order. Close during an in-flight load does not prevent later publication. Ready/error/scrub callbacks and delayed thumbnails carry no source generation. | Give each source request a generation and cancellation lifetime. Dispose rejected engines, and suppress callbacks for retired sources. |
| P06 | P1 | **Frame/clock waits are not cancellable.** `NextFrame` has a naked `<-e.frameQueue` and an indefinite paused polling path (`playback.go:698`). Close drains but does not close frameQueue or send a terminal event to blocked consumers. `clock.go:142` waits for PTS without a stop/deadline; Pause can interrupt its polling, but retirement cannot reliably do so. Convert skip/chapter/fullscreen seek handlers call Seek synchronously. | Propagate cancellation through frame and clock waits and FFmpeg I/O; execute transport commands off the UI thread. Require bounded exit on pause, close and source replacement. |
| P07 | P1 | **Seek channel lifetime is unsafe.** OnSeek snapshots a channel under the mutex, releases it, then sends. Load/Close closes that channel outside the lock. A concurrent sender can panic on a closed channel. Closing an old channel also leaves buffered requests available to its loop, whose `v.Seek` resolves the current engine. `seekLoop` reads the mutable `v.seekCh` on goroutine startup. | Pass a session-owned mailbox explicitly to its worker; cancel workers without closing a channel that external senders still hold; reject retired commands. |
| P08 | P1 | **Backward step returns the wrong frame.** `playback.go:338` seeks to current − step duration − 2 seconds, then consumes only `-frames` frames. For Step(-1), this returns the first decoded frame near that earlier seek, not the frame immediately preceding current. It uses clock time rather than the last presented frame PTS. | Decode forward to the preceding presentation timestamp; define VFR stepping using actual frame timestamps. |
| P09 | P1 | **Playback errors leave authoritative state stale.** The non-EOF playbackLoop error branch sets widget error/playing=false but never clears `v.playing` or notifies state subscribers. A subsequent Play sees true and may return without starting a consumer. Fatal decode errors are converted into a last-good-frame followed by EOF in NextFrame, so the caller can mark failed media completed and auto-reload it. | Distinguish terminal error from clean EOF and publish a consistent stopped/error state before returning. |
| P10 | P1 | **Engine access can race teardown.** Audio/subtitle getters, selectors, volume and mute access `v.engine` without v.mu. Other methods snapshot it then use it after releasing the lock; asynchronous Close can free its C resources concurrently. Engine.SelectAudioTrack rebuilds audio context/player without a transaction covering concurrent Seek/Close/demux access. | Session ownership must cover the whole operation, including track changes and native resource disposal; merely locking pointer reads is insufficient. |
| P11 | P2 | **Source-specific open information is lost.** LoadDVD/LoadURL retain only currentPath. EOF reload calls ordinary Load, losing DVD title selection and URL options. Scrubber/thumbnail decoders reopen a bare path without DVD demuxer/title or network options (`scrub.go:174`, `engine.go:1416`). OpenDVD does not invoke the Rip software CSS preparation stage. | Preserve source kind, selected title and options through auxiliary decoders and reload. Treat direct encrypted-disc playback as unverified; do not equate Rip CSS support with Player support. |
| P12 | P2 | **Source UI remains stale.** Load installs chapters only when nonempty and does not clear thumbnail cache; a chapterless source inherits old chapters and thumbnails. Convert track selectors capture names at pane construction, while Player builds the pane before asynchronous load completes. Player Clear sets only its local Options.PlayerFile=nil; the host state.playerFile remains populated and rebuilds a loaded-source pane (`player/view.go:62`, `player_module.go:76`). | Reset source metadata on every load and rebuild track/chapter controls from Ready events. Clear the host source reference through an explicit callback. |
| P13 | P2 | **Growing-file watcher has no lifetime limit.** `inline_player.go:1150` polls forever; Close/source switch never cancels it. Later growth can Load and Play the retired source. | Bind watcher to source generation and cancel on retirement. Preserve growing mode when reopening. |
| P14 | P2 | **DVD pane ownership is incomplete.** Title buttons launch unrestricted concurrent LoadDVD calls and discard errors. Its local player closes only through its Back button, while Queue navigates through the shared host machinery. Previous-title handler mutates selectedTitle inside loadTitle, then computes the chapter index from the already changed value. | Cancel superseded title requests, report errors, dispose local player on every exit, and compute navigation target once. |
| P15 | P2 | **Partial open cleanup is missing.** loadViaOpen returns on open failure without closing the candidate engine. Engine.Close returns immediately if !running (`playback.go:956`), even though openFinalize can already have allocated codecs/format resources before failing. | Dispose partially constructed resources independently of whether playback started. |

## Performance findings requiring measurement

- SW decoding deliberately forces one thread (`engine.go:1274`); changing this blindly would undo a stability constraint. Profile software and hardware modes separately after ownership is repaired.
- Full-resolution RGBA frames allocate in `framepool.go:84`; repository search finds no caller of ReleaseFrame. At 1080p/60, one RGBA allocation/copy per frame is about 475 MiB/s, before scaling and texture upload. This is calculated traffic, not measured allocation throughput. The eight-frame queue holds about 63 MiB at 1080p and 253 MiB at 4K. Safe reuse requires explicit ownership across the widget, callbacks and caches.
- Widget scaling already reuses drawBuf; preserve it. Idle SMPTE rendering still allocates buffers. Playback queues UI time/frame callbacks each frame and Convert additionally queues progress updates. Measure pending work and frame age before deciding a coalescing rate.
- Thumbnail extraction uses an independent decoder and checks e.stop during extraction. It is not completely uncancelled. However, delayed startup opens before those checks and callbacks have no source-generation protection. Measure initial-load and background seek I/O.
- Clock waits sleep a media-time delta as wall time without dividing by speed (`clock.go:142`); non-1x pacing deserves timestamp measurements. A/V offset waits use pts+offset, while SyncVideo compares raw pts; offsets above the drop threshold can provoke drops. Validate both signs under normal playback.
- The seekGen/lastSeekGen logging defect is already fixed at `playback.go:607`. Frame tracing is opt-in. Do not claim the historical log-spam bug remains or remove useful diagnostics without measuring volume.

## Repair sequence and acceptance

1. **Restore lifecycle ownership:** one active source generation and one presentation consumer; retire/join workers; cancellable frame/clock/I/O waits; consistent terminal states. Cover rapid pause/play, close while loading, load A then B with A finishing last, EOF during source replacement, and track switch during close using controllable fake-engine tests.
2. **Restore transport correctness:** use actual FFmpeg constants, newest-wins seek requests, preview versus committed seek, accurate returned PTS, correct backward step. Validate paused and playing seeks, drag release, chapter jumps, long GOPs, VFR and EOF. Keep this coordinated with the lifecycle change rather than stacking independent decoder patches.
3. **Restore module/source state:** rebuild metadata on Ready, reset chapters/thumbnails, clear the host source, scope callbacks/peer playback to the active module, preserve DVD title/network options, dispose partial opens and cancel growing-file watchers.
4. **Measure and tune:** neutral local H.264/HEVC samples at SD/1080p/4K, with audio and without, interlaced DVD output and VFR. Record load-to-first-frame, command-to-presented-frame, dropped frames, A/V drift, CPU, memory, allocation traffic and log rate. Compare identical sources and settings. Set acceptance thresholds from the test machine and retain measurements.
5. **Real-media acceptance:** encrypted DVD → Rip intended title/scenes → Convert known format → playback, including pause/resume, seek, EOF and navigation away/back. Review the runtime log and update PLAYER_DEBUG with actual session observations before landing player fixes. Upscale remains downstream of this ladder.

The retained libVLC design remains an option, not a functioning fallback. Reintroducing it requires the approved SDK/CI/guarded-control prerequisites and explicit direction; this audit does not authorize changing the backend or workflows.
