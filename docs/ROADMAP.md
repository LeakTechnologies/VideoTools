- **Dev74 shipped/released** (published 2026-09-13, tag `v0.1.1-dev74`, `b6f90be6`): (1) the rip view now detects scene-segmented discs — `DetectSceneSets` bins scanned titles into whole-movie copies (the longest run + near-equal durations) and scene segments (shorter independent titles), tolerant of the duplicate-duration quirk on the `Red Hairy Teens (2008)` disc (T01/T02 5926/5932 s runs, segments T03–T07 ≈ 866/615/1978/1331/1141 s). (2) **Cell-accurate VOB-concat fallback** — the root-cause fix for wrong segment content: Windows builds can't open the source with ffmpeg's dvdvideo demuxer (libdvdnav rejects it), every rip falls back to whole-file VOB concatenation, and a shared-VTS extra title therefore ripped the movie's opening. `ifo.TitleInfo` now carries per-title PGC cells (VOBID/CellID/FirstSector/LastSector) read from the PGC cell position + cell playback tables, and the executor (`cellConcatList`) builds a concat list that slices each VOB to the selected title's cell byte ranges (sector×2048, adjacent cells coalesced per VOB), wired into both the primary concat path and the dvdvideo-failure retry. Skipped when the cells span the whole set, on angle discs, or when any cell VOB can't resolve — all with a logged fallback. - **Dev73 = per-title PGC duration scan consistency** (published 2026-09-13, tag `v0.1.1-dev73`, `cfa9e879`): on multi-PGC VTS discs (scene-segmented titles — e.g. the `Red Hairy Teens (2008)` disc with 7 titles in one VTS), the rip scan cached ONE `ifo.ReadTitleInfo` per VTS and the reader only ever looked at the first title-domain PGC — so T01–T07 all displayed the full movie's "1h 38m" even though T03–T07 were 14/10/33/22/19-minute scene segments. New `ifo.ReadTitleInfoForTTN` selects the PGC served to a specific VTS title (PGCI_SRP TitleNr byte via the shared-PGC rule, with index fallback for authors that don't populate it); the scan caches per (VTS, TTN) so every title card shows its own duration and chapters, and the rip executor resolves the selected title's TTN from the VMG TT_SRPT so embedded chapters and the IFO-sourced `-t` cap describe the ripped title, not title 1. Verified end-to-end on the `Red Hairy Teens (2008)` VIDEO_TS: T01/T02 5926/5932 s (15 ch), T03–T07 866/615/1978/1331/1141 s (3 ch each). Unit tests cover the shared-PGC rule, the index fallback, and ttn=0 legacy equivalence.
- **Dev72 shipped/released** (published 2026-09-12, tag `v0.1.1-dev72`, `c0e21121`): ISO 9660 fallback for non-UDF disc images — some grey-market DVDs carry a burner-written UDF bridge whose anchor scans as PVD/IUVD/PD/LVD/USD/TD tags but whose LVD fails to parse — the old UDF reader reported `LVD not found in VDS` and the disc (reported on `Blowjob Fantasies 3`) could not be scanned or ripped. A new native ISO 9660 reader (`internal/dvd/iso9660`) parses the PVD at sector 16 (magic `CD001`, type 1), walks directory trees with spec-correct single-byte `.`/`..` identifiers and `;version`-stripped names, folds multi-extent continuations (flag 0x80), and mirrors the UDF reader surface (`ReadFileData`/`ExtractDirectory`). Both the scan path (`scanISOViaUDF`) and the extraction path (`resolveISOWithUDF`) try UDF first and fall back to ISO 9660, logging which backend served the files; when both fail the error names both backends — a damaged image is never falsely called corrupt. Verified on the reported ISO: IFO byte counts (12288/94208) match the ISO 9660 listing and both titles scan with chapters/audio/duration.

- Windows and Linux package workflows green on release candidate.

- No known P0/P1 regressions in conversion, queue, or subtitle sync.
